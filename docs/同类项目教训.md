# 同类项目教训（内部文档，2026-08-19）

深读四个同思路项目（howells/fiction、haowjy/creative-writing-skills、Deland78/claude-writing-skills、rhavekost/author-toolkit）的结论。原始分析已归档在各自会话，此处只留可行动的教训。

## 一、四个项目共同验证了我们的两个差异化

1. **承诺账本没有人做**。四个项目里 setup/payoff、伏笔、读者契约全部只作为"批评期检查项"散落，没有一个有跨章的承诺生命周期账本。我们的核心机制在这个生态里是独一份。
2. **发现式写作没有人支持**。howells 明写"Don't skip this（大纲）"；Deland78 是 L1→L5 硬流水线；haowjy 全库只有一句提及；author-toolkit 明确偏大纲派。"发现式一等公民"是空白生态位。

另有一条直接验证我们的决策：haowjy 在 0.5.0 **删掉了**拆分的起草/过渡/改稿 agent，理由是"拆分会破坏声音连续性"——正是我们把执笔模式聚合进一个 /draft 的原因。

## 三、值得偷的设计（M2+ 候选）

- ~~⚓ 锚定（howells）~~：已否决——圣经里的设定本就全部可依赖，再分"锚定/普通"两级是给作者添一个要维护的状态，违背精简。
- **引用门控**（Deland78）：无出处引用的意见只是 advisory，不能写入 canon。我们已有"每条事实带出处章节"，规则升格：无出处不入圣经。
- **文风文件的两个判据**（haowjy）：声音测试（只读该文件能否写出作者认得出的散文）+ 简洁测试（一遍能内化，否则是过度规定）；意图性风格进 styles、无意识口头 tic 进 issues。→ M2 文风机制的现成设计。
- **PreCompact hook**（Deland78）：上下文压缩前强制落盘会话状态。→ M2 候选，护栏 hook 的兄弟。
- **模型分级按损伤半径**（Deland78）：承重结构（前提/大纲）用强模型，单场景损伤半径小可用轻模型。→ 记着，不硬编码。
- **%%NOTE%% 内联批注**（howells）：作者在正文里用阅读视图不可见的注释给 AI 留话。→ 作者主笔模式的天然通道，M2 候选。
- **read-only 沙箱跑连续性检查**（haowjy）：检查者只报告不动稿。→ /revise 设计时采用。
