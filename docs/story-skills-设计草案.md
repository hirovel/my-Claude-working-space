# Story Writing Skills 设计草案 v0.2

> 目标：打造一套小说写作 skills，在小说创作领域达到 mattpocock/skills 在工程领域的地位。
> v0.2 修订原则：**不照搬工程隐喻。** 从 Matt 只继承"元层"（怎么写 skill 本身）；
> craft 层（写什么样的流程）以创意写作课程为源——首先是布兰登·桑德森的 BYU 318R 课程。
> 语言：skill 全部中文编写。

## 〇、v0.1 → v0.2 的关键修正

| v0.1（工程移植） | v0.2（写作原生） | 为什么改 |
|---|---|---|
| 场景卡 = 工单 + 阻塞边 | 场景是叙事单元，无依赖图；大纲式作者可选用场景卡做规划 | 故事基本线性，依赖图是伪需求 |
| 场景验收单 = 测试 | 场景判据：推进了哪条承诺？结束时什么值变了？ | 判据保留（元原则），语言换成 craft 的 |
| 单一流水线 对齐→spec→拆票→实现 | 双模式：发现式 / 大纲式，且按情节·人物·世界观三维度分别定位 | 桑德森：这是光谱，且可按维度混合 |
| 伏笔账本 | **承诺账本**（承诺—推进—兑现） | 伏笔只是承诺的一种；承诺是更本质的契约 |
| 圣经必须事前建 | 大纲式事前建；发现式靠**收割**事后建 | 发现式作者不该被逼先建圣经 |

## 一、两个源，各取什么

**源 A：mattpocock/skills —— 只取元层**（见《matt-skills-精读笔记.md》）
双轨调用（用户触发/模型触发）与 router；状态外置到文件（上下文易失，文件持久）；
可检查、穷尽式的完成判据；锚点词；正向表述；剪枝纪律；explore/exploit 分相；
grilling 原语（事实归 agent 查，决策归用户定）。

**源 B：创意写作课程 —— 取 craft 层**（首批：桑德森 BYU 318R）
- **发现式写作 vs 大纲式写作**：光谱而非二选一；可按情节/人物/世界观分别定位
  （桑德森本人：情节大纲式 + 人物发现式）。
- **承诺—推进—兑现**（Promise / Progress / Payoff）：故事对读者的契约。
  开篇基调是承诺，人物欲望是承诺，类型是承诺，伏笔是承诺；
  推进必须可感知；兑现要"意料之外、情理之中"。
- **情节框架**是工具箱不是教条：三幕、英雄旅程、尝试—失败循环（"是的，但是 / 不，而且"）。
- **人物三滑尺**：好感度、主动性、能力——三个可独立调节的量，人物弧线=滑尺的移动。
- **世界观**：冰山错觉（展示 10% 暗示 90%）；魔法定律（限制比能力有趣；
  用魔法解决问题的能力与读者理解成正比；先深挖已有再添新）。
- **修订**是独立于初稿的阶段；反馈原则"描述问题，不开药方"。
- 最重要的能力是**写完**。

## 二、M1 最小框架：4 个 skill + 1 个纪律

### 状态文件（由 /setup-story 按模式裁剪生成）

```
<作品名>/
├── bible/          # 故事圣经：premise.md, characters/, world.md
│                   #   大纲式=事前写；发现式=由"收割"事后长出来
├── ledger/
│   └── promises.md # 承诺账本（体系核心，两模式共用）
├── outline.md      # 仅大纲式（或混合模式的大纲维度）
├── manuscript/     # 正文，一章一文件
└── notes/          # 灵感碎片堆（explore 素材，无结构）
```

**承诺账本条目格式（锚点词：承诺/推进/兑现）**：

```md
- [开出 第1章] 主角对妹妹发誓查明父亲死因 → 推进：第3章(线索)、第7章(嫌疑人) → 兑现：未
- [开出 第2章] 世界规则：御水术无法作用于活物血液 → 已被第9章依赖，不可更改
- [已兑现 第12章] 第4章反复出现的怀表 → 打开夹层
```

状态机：开出 → 推进(0..n 次) → 兑现 / 显式打破（打破也是一种兑现——需要在文中处理，
而不是遗忘）。

### Skill 1：/setup-story（用户触发）

治什么：一上来就被流程绑架，发现式作者被逼写大纲。
核心访谈（grilling 原语，每题给推荐答案）：
1. **三维度光谱定位**：情节、人物、世界观各自是发现式还是大纲式？
2. 作品形态：连载/长篇/中短篇；视角策略；类型承诺（读者因为什么翻开这本书？——
   这是承诺账本的第一条）。
3. 据此生成上述目录：全发现式作者拿到的是几乎空的 bible/ + 账本 + notes/，
   而不是一堆待填表格。

### Skill 2：/develop（用户触发）——发展想法

治什么：想法没长成就硬写，或者反过来在设定里打转永远不动笔。
按维度光谱分流：
- 该维度**大纲式** → 盘问式发展（frontier 轮询），沉淀进 bible/ 与 outline.md。
  情节维度用承诺—推进—兑现组织大纲：先列本卷开出的承诺，再排它们的推进点和兑现点，
  框架（三幕/英雄旅程/尝试—失败）作为可选脚手架而非必填模板。
- 该维度**发现式** → 只做碎片挖掘（灵感、片段、金句进 notes/），明确拒绝结构化；
  盘问只问一个问题的深度："下一场戏需要知道什么？"其余留给写作现场。

### Skill 3：/write（用户触发）——写作循环

治什么：无判据地写、写完不记账。两模式共用同一循环，入口不同：
- 大纲式入口：从 outline.md 取下一场——写前明确这一场**推进哪条承诺**、
  结束时**什么值改变**（关系？信息？处境？）。
- 发现式入口：从"当前情境 + 人物此刻想要什么"直接向前写，不要求预先声明——
  桑德森：发现式作者的大纲在身后，不在前方。
- 共同收尾：调用**收割**纪律（见下）。
- 写作中遵守：视角纪律（谁的头脑，就只有谁的感知）；每写一段前重读正文尾部保持衔接；
  尊重用户对已写内容的手工修改（从磁盘重读，Matt writing-* 的规矩）。

### Skill 4：/story-help（用户触发）——router

罗列全部 skill 与使用时机；定义两条主流程（发现式/大纲式各一条）。
M1 阶段它很短，随体系生长。

### 纪律 1：harvest 收割（模型触发，被 /write 收尾调用，也可独立触发）

治什么：发现式写作的设定漂移与承诺遗忘——本体系最重要的原创机制。
每写完一章/一场，从**正文**中提取（正文是唯一事实源，圣经是它的索引）：
1. 新出现的设定事实 → 写入 bible/（发现式作者的圣经就是这样长出来的）；
2. 新开出的承诺 → 记入账本；已推进/已兑现的 → 更新状态；
3. 与圣经或账本冲突的内容 → 立即报告，让作者裁决改正文还是改设定
   （正文优先是默认推荐：读者读到的是正文）。
完成判据：本章每个专名、每条新设定事实均已核对入册；账本中每条"开出"状态的
承诺均已检查本章是否触及。

## 三、M1 之后（失败模式驱动，不预先建造）

真的用 M1 写 2–3 章，记录失灵点，再固化：
- 修订类：/revise（描述问题不开药方的反馈模式；轴分离但用 craft 语言重述）
- 人物类：三滑尺参考、视角深浅参考（模型触发词汇层）
- 跨会话：/chapter-handoff（交接文档）——连载刚需，一旦上量立即做
- 更多课程源：麦基《故事》（场景=价值转变——可强化 /write 的判据）、
  Save the Cat（节拍表模板）——同样只取 craft，不取教条

## 四、写 skill 的元规则（不变，来自 writing-for-agents）

一句话定位+超出范围；可检查穷尽式判据；模板内联、长参考外置；
锚点词全体系复用：**承诺 / 推进 / 兑现 / 收割 / 圣经 / 账本 / 光谱 / 盘问**；
正向表述；逐句剪枝。
