# 写自己故事的人的 Skills

我用来陪有想法的人写小说的 agent skills——不是内容量产。

写长篇小说很难。市面上的重型写作流水线试图替你接管过程：扫榜定方向、模块组装剧情、几百行流程代你执笔。但在接管的同时，它们拿走了你对故事的控制权，也会随着模型进化变成枷锁。

这些 skills 被设计得小、极简、可组合：只防真实的失误（跨章失忆、设定漂移、承诺烂尾），不规定你怎么写。发现式还是大纲式、谁来执笔，都由你定。改造它们，让它们变成你自己的。

## 安装（30 秒）

1. 把 `skills/` 下的目录复制到 `~/.claude/skills/`（或作品仓库的 `.claude/skills/`），或安装打包的 `.skill` 文件。
2. 找个目录，运行 `/setup-story-skills`（五分钟机械配置），再 `/brew` 把想法聊成故事。
3. 开写。

## 为什么有这些 skills

### 一：写到第 30 章，AI 忘了第 3 章

**问题**：模型的上下文有限，跨会话必然失忆。角色说出不该知道的事、设定前后矛盾，都是失忆的症状。

**解法**：状态外置。正文是唯一事实源，`bible/`（圣经）和 `ledger/`（账本）是它的索引，由 **harvest（收割）** 在每次写作后自动维护——发现式作者的圣经就是这样一章一章长出来的，作者永远不需要手动记账。

### 二：伏笔埋了，然后烂尾了

**问题**：开出的悬念、誓言、伏笔散落在几十万字里，作者和 AI 都会忘。

**解法**：**承诺—推进—兑现**。故事是对读者开出又兑现的承诺；**承诺账本**记录每条承诺的全生命周期，工作账本只留未兑现项，一眼读完，每次写作必读。词汇层见 [promises](./skills/promises/SKILL.md)。

### 三：被流程绑架

**问题**：多数写作工具假设你先有大纲。但发现式与大纲式是光谱，且情节、人物、世界观三个维度可以不同——许多成熟作者就是情节大纲式+人物发现式。

**解法**：档案按情节·人物·世界观三维度记录你的光谱和执笔模式（AI 主笔/共笔/作者主笔），之后每个 skill 都按你的方式配合你，`/brew` 还会边聊边校准它。发现式作者永远不会被要求先写大纲。

### 四：体系自己会变胖

**问题**：好东西见一个收一个，体系就会沉积成它反对的那种重型流水线。

**解法**：**`/absorb`**——吸收管道兼免疫系统。新的大师方法经过精读→蒸馏→安置在最便宜的层级；说不出"防什么失误"的内容不进 skill。

## Reference

按调用方式分两类：**手动**的只在你输入时触发，负责编排；**自动**的模型可以自己够到，承载可复用的纪律与词汇。

**主流程（手动）**

- **[setup-story-skills](./skills/setup-story-skills/SKILL.md)** — 配置一部新作品：目录、git/纯本地、偏好默认值。纯机械设置，每部作品一次。
- **[brew](./skills/brew/SKILL.md)** — 酝酿：把想法聊成故事的盘问访谈，边聊边沉淀并校准档案。
- **[draft](./skills/draft/SKILL.md)** — 起草：日常写作主循环，开工恢复记忆，收尾自动收工。
- **[absorb](./skills/absorb/SKILL.md)** — 把一套新的写作方法吸收进体系，保持极简。
- **[ask-hiro](./skills/ask-hiro/SKILL.md)** — 路标：不记得用哪个时问它。

**纪律（自动）**

- **[wrap](./skills/wrap/SKILL.md)** — 收工：会话结束的三步仪式——收割、交接、存档。
- **[harvest](./skills/harvest/SKILL.md)** — 收割：从新正文提取设定入圣经、承诺入账本，冲突即报告。

**词汇层（自动）**——在其他 skill 之下运行的共享方法，各自是其词汇的唯一出处：

- **[promises](./skills/promises/SKILL.md)** — 承诺方法：承诺·推进·兑现，账本格式与状态机。
- **[characters](./skills/characters/SKILL.md)** — 人物方法：欲望·恐惧·三滑尺·语言习惯的档案格式。
