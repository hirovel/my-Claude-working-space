为一部新作品建立工作目录。这是一次访谈，不是一张表格：逐轮提问，每题给出推荐答案，作者可以只说"都听你的"就用全部推荐值开始。

访谈只问四件事，其余一切留给写作过程中自然生长。

## 访谈

**第 1 轮 —— 作品本身**

1. 用一两句话说说这个故事。（说不清楚也没关系——那正是发现式写作的起点，如实记录即可）
2. 读者翻开这本书是想要什么？（爽感、悬疑、感动、奇观……）这是你对读者开出的第一条**承诺**，直接记入账本。

**第 2 轮 —— 光谱定位**

对情节、人物、世界观三个维度分别问：你倾向事先规划（大纲式），还是写着写着让它自己长出来（发现式）？

向作者说明：这是光谱不是二选一，且三个维度可以不同——桑德森本人就是情节大纲式+人物发现式。没有对错，选择只决定后续 skill 怎么配合你，不决定作品质量。拿不准就选发现式，随时可改。

**第 3 轮 —— 存稿管理方式**

给作者两个选项，把原因讲清楚，推荐 git：

- **git 管理（推荐）**：每次写作自动存档，你可以随时说"回到上周三的版本"；误删、改崩、大修反悔都能救回来；可推送到私有仓库作云端备份。全部由 agent 静默处理——你**不需要学任何 git**，唯一的痕迹是目录里多一个隐藏的 `.git` 文件夹。
- **纯本地**：目录里只有你的文件，最简单直接。代价是没有历史——误删和改坏无法回退，备份靠你自己（复制目录、网盘同步）。适合只想先试试，或已有可靠备份习惯的作者。

选纯本地的作者告知一句：以后随时可以无损转为 git 管理，一句话的事。

**第 4 轮 —— 放在哪**

作品目录的位置和名字。

## 建立目录

只创建**现在就有内容**的文件，目录跟着内容长，绝不预置空表格：

```
<作品名>/
├── story.md            # 故事档案：光谱定位、管理方式、访谈里说清的一切
├── ledger/promises.md  # 账本，此刻只有第一条：类型承诺
├── manuscript/         # 空目录，等第一章
└── notes/inbox.md      # 收件箱，附一行说明：灵感随手丢这里，格式不限
```

访谈第 1 轮若聊出了实质内容（人物、世界的雏形），才建 `bible/` 收纳；发现式作者的圣经留给收割去长。

选了 git：静默执行 `git init` 与首次提交，提交信息"开坑"。此后一切 git 操作都不出现在与作者的对话里。

## 完成

故事档案写齐、第一条承诺入账、目录建立（git 模式下已首次提交），并告诉作者下一步：想先发展想法就 `/develop`，想直接开写就 `/write`。
